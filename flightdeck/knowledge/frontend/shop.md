# Shop desktop surfaces

The market follows a VS Code-style discovery rail and left-aligned detail document, while inheriting Yotta's existing semantic colors and system typography. This is a scoped desktop surface, not a replacement global design system.

- Keep the search and result filters inside a 320px rail (280px on compact desktop widths). Results show real author/version/install state; do not invent ratings or download counts.
- Put the workflow identity, author and install/update/open action together in the detail header. Use actual content for details and release notes. Keep readable content width on large displays.
- In the sub-700px stress layout, reserve height for the result rail; `max-height` alone lets Grid collapse results below the search controls. The native desktop minimum is defined by `mainWindowMinWidth` in `internal/desktopapp/wails_tools.go` (currently 1180px); 900px and 620px captures are extra layout stress checks.
- The account trigger has a 32px avatar frame; its menu uses 48px. Render Identity `picture`, fall back to name initials on absent/failed images, and clear image-failure state when the URL changes.
- Keep the account trigger and cached profile lightweight; load the expanded menu only when opened. Startup and return-to-window focus call the non-interactive account refresh; routine status polling reads the native cache. `YOTTA_ACCOUNT_URL` opens the existing Account center without passing credentials. Nickname/avatar edits remain owned by Identity/Asset and return through verified userinfo, not client-supplied profile fields.
- The account menu shows nickname, plain "Account center", and sign-in/sign-out actions. Do not show a UID subtitle or manual profile refresh control. A missing nickname uses a generic user label/icon, never the identifier as a display name. Market creator presentation comes from Registry's current public-profile overlay and refreshes on selection/return to focus without resetting the selected detail tab.
- Windows remembered sign-in uses the existing securestore seam for refresh tokens only, scoped to data root and identity configuration. Never put access/refresh tokens in localStorage or config JSON. Transient network failures retain remembered login; explicit invalid grants clear it. If sign-out cannot clear the stored credential, show failure rather than falsely reporting success.
- Workflow publication uses one compact version input with major/minor/patch suggestion buttons. Default to the next patch of the highest published version. Enforce the same three-integer format and strictly increasing versions in the UI and Registry; installed versions only update to a higher semantic version.
- Detailed descriptions, instructions and release notes use the shared lightweight Markdown editor (Nuxt UI Editor, the same underlying editor as YueLi ContentEditor), with rich toolbar, source and preview modes. Keep Tiptap core and extensions on the same pinned release. Character limits follow Unicode characters, not UTF-8 byte counts.
- Publication is split into listing, documentation and version sections. Restore metadata from the previous release before enabling edits; on lookup failure keep publication blocked with retry, rather than silently replacing prior metadata with defaults.
- Authenticate at the publication entry before initializing or opening its form. Only explicit `LoginRegistry` / native `Session.Login` can open the browser; API `Session.Token` may silently refresh but otherwise returns an authentication problem. A cancelled or superseded login must not open a stale form. If authentication expires while editing, keep the modal and draft, offer explicit sign-in in place, and never auto-publish after sign-in. Publication forms do not dismiss on outside clicks or browser focus changes.
- Reuse IconPicker for public workflow icons. `workflowIcons.ts` loads local 128-icon packs on demand; do not import the full Tabler JSON into an application chunk or rely on a remote icon service for chosen icons.
- Keep summary distinct from detailed Markdown and instructions. Metadata filters and installed-ID scope go to Registry before pagination; frontend-only filtering of a limited page misses valid results. Release-history content remains versioned; author profiles use the verified Identity read model.
- Keep the normal publication form readable at 720px height; reduce default textarea rows and group spacing before increasing dialog height. Retain scrolling for smaller windows and expanded errors.

Implementation: `frontend/src/components/workflow/WorkflowMarketPanel.vue`, `WorkflowVersionInput.vue`, `frontend/src/components/AccountAvatar.vue`, `RegistryAccount.vue`, and the publication section of `frontend/src/views/WorkflowsView.vue`.
