# 图片录制与分辨率自适应 Run context

## Product truth

- 一个图片资源可以包含多个分辨率变体；这些变体表达同一视觉目标，不是时间版本历史。
- 精确分辨率变体优先。缺少精确档时，标准同比例分辨率允许使用最近档位的一次性缩放派生物。
- 原始 Workflow Source、原始变体和用户显式内容不得因一次 Run 被修改；派生物属于可重建缓存。
- “新增当前分辨率”必须真正打开截图工具；背景遮罩存在但截图工具不可操作是阻断性失败。

## Runtime decisions

- 选档、目标几何读取、比例计算、缩放和派生缓存发生在编译或 Run 建立阶段，不进入逐帧截图和模板匹配热路径。
- 精确 2K 变体直接使用；只有 1080p 时可为标准 2560×1440 生成 4/3 缩放派生物；宽高比明显不一致时
  不做非等比拉伸，返回可操作诊断或要求补录。
- 同一 Run 中相同源 Blob、目标尺寸和缩放算法版本共享同一派生物。缓存键至少覆盖 Source/资源内容、
  目标捕获几何、缩放算法版本和 compiler build。
- Run 执行仍消费单一确定模板；不得在轮询中遍历变体、建立多尺度金字塔或增加 map/mutex 查询。
- 生成的运行副本不出现在用户工作流列表，不制造另一份可编辑工作流。

## UI language

- 用户动作描述结果，不暴露 Compiler 或渲染实现。“编译”和“预渲染”都容易误导。
- 如果需要显式入口，优先使用“优化运行”；常规 Run 应能自动准备，按钮只用于提前准备、查看状态或诊断，
  不应成为运行成功的必要步骤。

## Acceptance

- 从资源库和工作流图片变体 Modal 均可进入可操作截图界面，取消后 Modal/遮罩状态正确恢复。
- 2K 目标有 2K 变体时选择精确档；只有 1080p 时只在 Run 建立阶段缩放一次，并在逐帧匹配中复用。
- 不同比例目标不会静默拉伸；错误能说明需要哪个分辨率变体。
- 原始 Source 和图片资源不变，重复 Run 命中可重建缓存。
- 定向回归、`task check` 与 CLI 桌面视觉验收通过。
