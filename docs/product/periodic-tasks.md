# 周期检测与可恢复处理

工作流内的周期任务与主流程属于同一次运行。它们共享变量，但分别保存执行位置、循环状态和等待时间。

## 连接方式

- **周期任务**：运行开始 → 周期任务的输入；“每次执行”连接日志或检测节点。次数为 0 时持续运行，停止输入结束任务。第一次立即执行，后续按间隔触发。
- **监测任务**：“主任务”连接业务流程，“每次执行”连接检测。条件成立后接回该监测任务的“打断”输入，“处理”连接处理流程。处理分支结束后主任务继续；“停止”结束监测及主任务。
- 主任务自然结束也会结束其监测。检测、处理和主任务的未处理失败会结束所属任务；需要恢复的业务错误应连接对应错误分支。

一次检测尚未结束时不叠加下一次，也不补跑错过的次数。处理期间暂停检测；处理结束后再次检测仍成立时会再次处理。只想触发一次时，用变量记录已处理状态，或连接停止输入。

10ms 可以用于轻量日志或状态检测，但不是实时系统精度保证。截图、网络和插件启动的耗时会影响实际频率；周期超时会在运行记录中显示跳过次数。任务数量、并发操作和保留结果有独立上限，历史记录按页存储，不随一次运行无限堆积在内存中。

## 暂停与恢复

暂停保存整个任务的执行帧和剩余有效时间。例如一个 5 秒等待已过去 2 秒，处理用了 8 秒，恢复后仍剩 3 秒。移动和识图在等待边界暂停；恢复后重新获取坐标或截图。持有的键鼠输入先释放，处理完成后再恢复仍有效的持有动作。

网络请求、脚本和插件调用作为原子操作等待完成或取消，不宣称可随时保存任意第三方调用栈。界面先显示正在暂停，完成交接后才显示已暂停。停止运行会取消并等待清理。

独立工作流可同时运行；达到并发上限后继续排队。Windows 桌面输入由所有运行协调，避免两个任务同时争抢同一键鼠。等待设备不妨碍其他任务的日志和数据处理。

## 来源独立的坐标移动

1. 新建“世界位置”类型变量。
2. 在监测任务的检测分支读取位置。HTTP 文本接“解析世界位置”；插件或 OCR 提供的标量接“构造世界位置”。输出接“写入变量”。
3. 主任务接“移动到坐标”，选择该位置变量，填写目标、检测间隔、到达容差和减速距离。

位置包含坐标、朝向、坐标系、单位、轴向和样本时间。90° 轴向表示第一坐标轴正方向对应游戏朝向 90°，由位置提供者定义。移动算法不引用特定游戏或 HTTP 地址。远处持续前进，接近时缩短步幅；数据过期先停下，重新获得新样本后再继续。此节点不提供绕障或路径规划。

工作流运行时会自动准备所引用插件的采集服务，无需先打开扩展面板。首次坐标按移动节点设置的超时等待；开始移动后，数据过期仍先松键，短时间内无法恢复则走“坐标不可用”分支。

## 面板按钮与运行信号

“监听面板信号”选择面板及按钮（留空接收整个面板），从“收到信号”连接处理分支，从“主任务”连接正常流程。每次交互输出按钮/组件ID、事件ID和数据，处理分支按顺序执行；主任务结束或进入“停止任务”时释放监听。没有主任务连线时持续监听，直到停止监听或停止运行。

多个运行显式监听同一面板时，各自收到每次交互。只获取面板引用或读取数值不会订阅。面板一直保留，运行结束只释放自己的监听。程序写值不会冒充用户点击。

“等待面板交互”只接收走到该节点之后的一次点击，适合“下一步”；提前点击不留到后面的等待节点，可在检查器设置超时。“发送信号”“监听信号”“等待信号”按名称在当前Run内通信，支持JSON数据；等待信号的超时设0表示一直等待。跨Run的同名信号互不干扰。

监听期间保留排队事件，暂停时不执行处理分支，恢复后继续；等待超时只计算活动时间。每个订阅最多排队64个事件、1MiB数据，超量明确进入失败分支，不无限增加内存。快速点击会在面板端顺序提交；请求失败显示错误并停止尚未提交的点击，不自动重试未知结果。

例如：按钮事件→增加计数；按钮事件→写入模式变量，周期任务读取模式切换分支；主流程→等待交互→下一阶段。接收点击由事件唤醒，不必用周期任务轮询按钮。

## 本地开发数据转换

退出使用该资料目录的 App，先预览，再加 `--write`。工具先备份并持有资料目录写锁，不在 App 中保留旧执行器。

```powershell
go run ./cmd/yotta-runtime-migrate --profile C:/path/to/profile
go run ./cmd/yotta-runtime-migrate --profile C:/path/to/profile --write
go run ./cmd/yotta-runtime-migrate --navigation-profile C:/path/to/profile
go run ./cmd/yotta-runtime-migrate --navigation-profile C:/path/to/profile --write
```

第一组转换运行历史摘要，保留全部事件和值。第二组针对本地终点式 Move v1 工作流展开显式坐标采集分支，保留目标、轴向和资源；有后继连线的旧移动节点要求手动接线，避免猜测业务分支语义。独立 Node Contract v2 文件可用 `--node-contract <file>` 转换；签名插件包通过作者重建，不改签名字节。
